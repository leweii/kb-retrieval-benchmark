A · Method

What was compared

DimensionValues
Knowledge-base size300 / 900 / 3000 documents, nested (300 ⊂ 900 ⊂ 3000); composition in Appendix B
ModelsClaude Haiku 5.5, Claude Sonnet 5.5 (Anthropic API, effort medium); DeepSeek V4.1 Flash (DeepSeek API, default effort high — that API has no medium level)
RetrievalR1 grep (regex over files + read) · R2 BM25 · R3 hybrid (BM25 + dense, RRF) · R4 enhanced hybrid (QMD-style: Haiku query expansion → BM25 + dense → RRF → Haiku rerank of 30 candidates) · R5 LLM-wiki navigation (start at index.md, follow links, may open raw notes) · R6 LLM-wiki + hybrid search
ModeSingle-shot: retrieve once with the question, top-8 passages to the model · Two-round: if insufficient, the model writes 1–3 associative queries for one more retrieval, then answers or refuses · Agent: the model calls tools (search / grep / list / read) for up to 12 steps

Components

  • Embeddings: qwen3-embedding-8b (OpenRouter, pinned to DeepInfra); brute-force cosine in numpy, no vector database. Chunks split on markdown headings, ~600 tokens.
  • LLM-wiki: Claude Haiku 5.5 digests each note (summary, key facts, entities); code assembles index / topic / source / entity pages. In a 50-document blind review Haiku and Sonnet digests were on par.
  • Shared prompt: facts must come from the knowledge base; general knowledge may interpret and connect KB content but not fill gaps; say clearly when the KB lacks the answer. Agent search strategy: key terms (plus English keywords for non-English questions) → associations if nothing relevant → each missing piece of a multi-step question → only then refuse.

Grading and metrics

MetricDefinition
AccuracyMuSiQue answerable questions: answer matches the reference or an alias (judged by Claude Opus 5.5). Only the 168 clean questions count: 32 questions that any tested model answers without the KB were removed
Full evidence foundEvery evidence document of a multi-hop question appeared in retrieval results or was opened (wiki source pages map back to their raw note)
False refusalShare of MuSiQue / BRIGHT answerable questions answered with "not in the KB"
Says "not in the KB"Share of unanswerable questions where the answer clearly states the KB lacks it; answering anyway counts as hallucination
p50 latencyMedian end-to-end time from question to final answer, measured under concurrent load
Cost per questionModel calls + retrieval APIs (embeddings, R4 expansion and reranking) at each provider's actual prices
RoundsCalls to the tested model per question: single-shot = 1; two-round = 1–3; agent = one call per round, up to 12 rounds plus one forced answer at the cap (max 13). "Hit step cap" = share reaching the 12-round cap
Tool callsTotal search / grep / list / read calls per question (the two-round extra search counts as 1); an agent may call several tools per round
  • Grader: Claude Opus 5.5 (not a tested model), via Message Batches; all 31,713 answers graded. BRIGHT is open-ended and NoLiMa mainly tests associative retrieval, so these two are graded on retrieval and refusal only.
  • Recommendation rule: among combinations with ≥ 70% correct refusals and ≥ 30 graded MuSiQue questions — best quality = highest accuracy; best value = cheapest within 5 points of it; Flash-tier = Haiku / DeepSeek only.
  • Key differences use paired McNemar tests on the same questions: at 3,000 docs DeepSeek agent+grep 70% vs Sonnet 62% (p = 0.015).

Limitations

  • Public datasets are not personal md notes: many notes on one project, conflicting versions and wording mismatch between writing and asking are not covered.
  • Claude ran at effort medium, DeepSeek at high — reasoning budgets are not fully matched.
  • Latency was measured under concurrent load; compare across API providers with care. Agents were capped at 12 steps; about 20% of DeepSeek's questions hit the cap.
  • R4 reranks with Haiku instead of QMD's Qwen3-Reranker (same recall in a 16-query check). Qwen 3.8 Flash was not run (API credits).
